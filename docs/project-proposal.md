1. Problem Statement

University students and staff may lose personal belongings such as keys, wallets, student ID cards, and electronic devices on campus.

Information about lost and found items may be scattered across informal channels, such as WhatsApp groups, social media, and communication with university personnel. This can make it difficult to search for missing belongings and track their status.

Our project proposes a centralized web-based system to organize lost and found reports and support the recovery of personal belongings.

2. Supporting Evidence

A student survey has been prepared to investigate experiences with lost and found items at university.

The survey examines:

* Previous experiences with lost or found items.
* Methods used to report or search for missing belongings.
* Difficulties in accessing lost item information.
* Interest in using a centralized lost and found website.
* Features students consider most useful.

3. Stakeholder Identification and Analysis

Stakeholder	Interest and Needs
Students	Report lost or found items, search reports, and submit ownership claims.
University Staff	Report found belongings and help users locate items.
System Administrators	Review ownership claims and manage item statuses.
University Administration	Benefit from a more organized lost and found process.

4. Proposed Solution

The proposed solution is a web-based Lost & Found Management System designed for university users.

The system will provide:

1. User registration and login.
2. Lost item reporting.
3. Found item reporting.
4. Item searching and filtering.
5. Ownership claim submission.
6. Administrative claim review and item status management.

5. Expected Outcomes

The project aims to:

* Centralize lost and found information.
* Make item reports easier to search.
* Reduce reliance on informal communication channels.
* Support the verification of ownership claims.
* Improve the organization of the lost and found process.

6. Feasibility Assessment

The project is considered feasible within the course schedule because it focuses on standard web application functionality.

Proposed Technologies:

* Frontend: HTML, CSS, JavaScript
* Backend: Node.js, Express
* Database: SQLite
* Version Control: Git and GitHub
* Containerization: Docker
* Testing: Automated unit and integration tests

The first version will focus on a single university.

7. Initial Project Scope

In Scope:

* User authentication
* Lost and found item reports
* Item search and filtering
* Ownership claims
* Administrative claim review
* Item status updates

Out of Scope:

* Native mobile applications
* AI-based item matching
* Real-time messaging
* Online payments
* Automatic physical ownership verification
* External university system integrations

8. Assumptions and Constraints

* Users have access to the internet.
* The system is initially designed for one university.
* Ownership claims require human review.
* The team has limited development time.
* Personal information must be protected.

9. Potential Risks

Risk	Mitigation Strategy
False ownership claims	Administrative review and verification questions
Unauthorized access	Authentication and role-based authorization
Incorrect item information	Input validation and report editing
Development delays	Prioritized backlog and sprint planning
Technical failures	Automated testing and version control
